# Эксплуатация и безопасность

## Модель доверия

Linklab v1 рассчитан на доверенную изолированную LAN. В протоколе нет
аутентификации, pairing, авторизации и идентификации клиента.

- Не публикуйте порт Linklab в Интернет.
- Не передавайте секреты по неаутентифицированному `ws://`.
- Ограничивайте вход firewall и сетевой сегментацией.
- Сохраняйте конечные `max_connections` и лимиты моделей.
- Логируйте адрес источника, admission и ошибки протокола без payload и
  небезопасных диагностик peer.

По умолчанию сервер слушает `127.0.0.1`; внешний или wildcard host задаётся
явно. Для `wss://` приложение передаёт `ssl.SSLContext`. Доверенный или pinned
сертификат может подтвердить сервер, но не клиента. Если нужна идентификация
клиента, добавьте аутентифицированный gateway или новую версию протокола.

DNS-SD/mDNS не аутентифицирован и может быть подменён. Это только routing hint;
решающими остаются subprotocol, handshake и проверка WSS-сертификата. Для
предсказуемого маршрута используйте прямой URI.

## Ограниченные ресурсы

| Ресурс | Значение по умолчанию |
| --- | ---: |
| Очередь input клиента | 16 000 входных фреймов |
| Очередь playback клиента | 2 000 мс |
| Очередь handler сервера | 32 000 входных фреймов |
| Неотправленный output сервера | 500 мс |
| Входная очередь WebSocket | 16 сообщений |
| Write limit WebSocket | 65 536 байт |
| Соединения сервера | 8 |

Перегрузка не скрывается бесконечным ожиданием: она отклоняет активацию,
прерывает input/playback, отменяет response, завершает conversation или закрывает
невосстановимое соединение. После `QueueOverflow` из `OutputWriter.send_audio`
terminal sequence уже запущен; повторять PCM нельзя.

Абсолютные лимиты декодера: сообщение WebSocket 262 144 байта, первое hello
16 384, глубина 8, 64 поля map, 32 элемента array, UTF-8 строка 65 536 байт,
identifier/reason/type 64 байта, неаудио binary 16 384 байта. Peer не может
увеличить эти лимиты. Compression отключён.

## Таймауты и reconnect

Значения транспорта: connect 10 с, handshake 5 с, ping 20 с, pong timeout 20 с,
close 10 с. Keepalive нельзя отключить. Сервер: waiting 60 с, input 120 с,
processing 120 с, согласованный idle 120 с.

Reconnect использует full-jitter exponential backoff от 0,5 до 30 с после 1001
или потери транспорта, но не после 1002/1008. ID, conversation и PCM не
возобновляются и не повторяются; активация без соединения отклоняется.

## Завершение и наблюдаемость

Используйте async context manager или `close()`. Завершение идемпотентно и
ограничено по времени. Не останавливайте event loop до завершения `close()`.

Передавайте `lumivox_core.logger.Logger`. Linklab напрямую вызывает `bind`,
`debug`, `info`, `warning`, `error`, `exception`, не настраивает logging процесса
и не скрывает ошибки logger. Структурные записи описывают listener/discovery,
admission, handshake, состояния, reconnect, ошибки, очереди, ID, диапазоны
фреймов, причины и задержки. Обычные логи не содержат PCM и полный текст
transcript/response. Ошибка 1002 означает несовместимость или дефект и требует
расследования, а не бесконечного retry.
